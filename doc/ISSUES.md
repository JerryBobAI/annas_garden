## 二、技术架构审视：是否最优？

### 当前架构

```
用户 → Next.js (SSR + CSR 混合) → API Routes → Supabase (PostgreSQL + Auth)
                                                    ↓
                                               RLS 安全策略
```

> ℹ️ 注：以下 A1–A4 是 Phase 0 规划时的架构审视记录，大部分已在 Phase 1–4 中解决。

### 核心判断：**架构能力不匹配产品愿景**

当前架构是一个**传统 CRUD Web 应用**的架构，适合「家长录题 → 孩子刷题 → 看统计」的工作流。但如果定位是**原生 AI 儿童教育平台种子**，这个架构在以下维度存在根本性不足：

#### A1. 缺少 AI 实时交互层

| 需要的能力 | 当前状态 | 差距 |
|---|---|---|
| AI 对话（流式响应） | 仅预留了 `api/ai/generate` | 无 streaming、无对话上下文管理 |
| 语音交互 | 完全没有 | 一年级孩子打字能力极弱，语音是刚需 |
| 多模态输入 | 无 | 孩子应能拍照提问、语音提问、涂鸦提问 |
| 实时反馈 | 靠 CSR 轮询 | 未用 Supabase Realtime / WebSocket |

#### A2. 数据模型面向「题库」而非「学习过程」

当前 11 张表核心围绕：**资料 → 题目 → 答题记录 → 错题**

这是一个**考试/刷题系统**的数据模型。缺少：

- **对话记录** — 孩子和 AI 的交互历史（这是最宝贵的学习数据）
- **探索轨迹** — 孩子主动发起的提问和好奇心记录
- **创作产出** — 孩子写的故事、画的画、编的歌谣
- **认知图谱** — 不只是「正确率」，而是理解深度、思维方式
- **情绪/兴趣标签** — 哪些内容让孩子投入、哪些让孩子无聊

#### A3. 内容生成模式过于依赖人工

| 当前模式 | AI 原生模式 |
|---|---|
| 家长手动录入题目 | AI 根据学期目标自动生成 |
| 家长审核 AI 生成内容 | AI 在安全边界内自主教学，家长看报告 |
| 固定题库 → 随机出题 | 实时根据孩子状态生成个性化内容 |
| 外部数据源同步 | AI 从互联网学习并转化为教学内容 |

#### A4. 前端交互模式不适合幼儿

| 当前 | 理想 |
|---|---|
| 点击选择题选项 | 语音回答、手写、涂鸦 |
| 页面跳转 | 连续的、沉浸式的学习流 |
| 文字为主 | 图像、动画、声音为主 |
| 被动接受题目 | 主动提问、探索 |

## 三、产品愿景审视：AI 原生儿童教育

### 当前产品的本质

> **一个漂亮的在线题库 + 做题器 + 错题本**

治愈风格做得很好，但底层仍是**Web 1.0 教育逻辑**：
- 知识被切割成碎片（题目）
- 学习被量化为指标（正确率、完成数）
- 孩子是**被测试者**，不是**探索者**

### AI 时代的儿童学习应该是什么？

一年级的孩子天然具备的能力：**好奇心、想象力、创造力、提问欲**。

AI 原生教育平台应该**放大这些天赋**，而不是用题库压制它们。

#### 🌱 核心转变

| 从（当前） | 到（AI 原生） |
|---|---|
| 家长出题 → 孩子做题 | 孩子提问 → AI 陪探索 |
| 选择题为主 | 开放式对话为主 |
| 正确率驱动 | 好奇心驱动 |
| 被动学习 | 主动探索 + 创造 |
| 刷题 → 记忆 | 理解 → 应用 → 创造 |
| 追踪「掌握了多少」 | 追踪「探索了什么、创造了什么」 |

#### 🌸 AI 原生功能愿景

**1. AI 学伴（Garden Fairy / 花园精灵）**
- 孩子可以随时语音提问：「为什么天是蓝的？」「7 + 8 怎么算？」「cat 怎么拼？」
- AI 用孩子能懂的语言回答，配合图片/动画
- 苏格拉底式引导：不直接给答案，引导孩子自己思考
- 记住孩子的每一次对话，形成个性化认知画像

**2. 创造工坊（Creation Studio）**
- **故事创作**：孩子口述 → AI 辅助编织 → 生成绘本
- **数学世界**：「用 12 块积木能搭什么？」→ 交互式探索
- **英语冒险**：和 AI 角色扮演对话，在场景中学英语
- **看图说话**：AI 展示一幅画，孩子描述，AI 追问拓展

**3. 好奇心花园（Curiosity Garden）**
- 每个问题是一颗种子
- 探索得越深，花开得越大
- 可视化孩子的知识探索地图（不是刷题进度条）
- 「Anna 今天种了 3 颗好奇心种子：为什么月亮会变形？三角形有几种？dog 和 cat 有什么不同？」

**4. 智能课程引擎（不是题库）**
- AI 根据学期大纲 + 孩子认知状态，实时生成教学内容
- 不是「第 3 周做 20 以内减法」，而是「Anna 上周对图形很感兴趣，今天用图形引入减法概念」
- 家长角色：从"内容录入者"变为"教育理念设定者"

**5. 家长洞察（不是刷题报告）**
- 不只是「今天做了 10 题，对了 8 题」
- 而是「Anna 今天对动物话题特别投入，主动追问了 5 个问题」
- 「Anna 的数学思维从具体计算开始向抽象模式过渡」
- 「建议这周引入简单的分类和比较概念，Anna 准备好了」

## 四、架构升级建议

### 如果要走 AI 原生路线，架构需要分阶段演进：

### Phase 0：保留当前（修复技术债务）
- 修复 T1-T5 高优先级问题
- 稳定现有功能作为 baseline

### Phase 1：引入 AI 对话核心
- 接入 LLM（OpenAI / Claude）实现流式对话
- 添加 `conversations` 和 `messages` 表
- 实现基础的 AI 学伴功能（文字版）
- 添加 AI 安全护栏（内容过滤、话题边界）

### Phase 2：语音交互
- Web Speech API / Whisper API 语音输入
- TTS 语音输出（让 AI 读给孩子听）
- 语音优先的交互设计

### Phase 3：多模态 + 创造
- 图片生成（AI 绘图辅助教学）
- Canvas 涂鸦（孩子画画）
- 故事创作工坊

### Phase 4：智能课程引擎
- 基于认知图谱的个性化内容生成
- 学期目标自动分解为学习路径
- 自适应难度和节奏
